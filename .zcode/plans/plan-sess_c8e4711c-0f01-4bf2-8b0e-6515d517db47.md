## Context

Web 前端（`learning-program-frontend`）的 ProfilePage.vue 目前选择头像文件后直接上传（`src/views/page/ProfilePage.vue:103-125`），非方形图片无法调整构图。后端对头像不做任何裁剪/缩放，只原样存储（≤2MB、JPEG/PNG/GIF/WebP + 魔数校验），因此裁剪必须在前端完成。目标：在「选择文件」与「上传」之间插入一个裁剪弹窗——方形比例裁剪、圆形视觉框（与圆形头像展示一致），确认后输出 PNG Blob 走原有上传链路。

方案：引入 cropperjs **v1**（`cropperjs@^1.6.2`，经典 API）。不用 v2（npm 最新 2.3.1）的原因：v2 是 Web Components API，在 Vue SFC 模板中使用需要改 vite.config.ts + tsconfig 的 `isCustomElement` 配置；v1 只需一个普通 `<img>`，零构建配置改动，自带 TS 类型。

## 改动文件

**1. 依赖**（`learning-program-frontend/`，包管理器为 pnpm）
- `pnpm add cropperjs@^1.6.2`

**2. 新建 `src/components/AvatarCropDialog.vue`**（仿项目 el-dialog 约定：v-model + title + width + footer 按钮）
- `defineModel<boolean>` 控制显示；prop `file: File | null`；emit `confirm`（携带裁剪后的 PNG Blob）。
- `el-dialog` width 480px，`align-center`；主体为固定尺寸容器（约 360×360）内放 `<img>`；footer 放「取消」「确认并上传」按钮。
- 打开时（`watch(visible)`）：`URL.createObjectURL(file)` → `nextTick` 后对新建的 `<img>`（`v-if="visible && srcUrl"` + `:key="srcUrl"`，保证每次打开都是干净元素）执行 `new Cropper(el, { aspectRatio: 1, viewMode: 1, dragMode: 'move', autoCropArea: 1, background: false, highlight: false, toggleDragModeOnDblclick: false })`。
- 确认时：`getCroppedCanvas({ width: 512, height: 512, imageSmoothingQuality: 'high' })` → `canvas.toBlob(blob => emit('confirm', blob), 'image/png')` → 关闭弹窗。
- 关闭时：`cropper.destroy()` + `URL.revokeObjectURL(srcUrl)`。
- 圆形裁剪框用 scoped CSS 覆盖 cropper 内部元素：`:deep(.cropper-view-box), :deep(.cropper-face) { border-radius: 50%; }`（标准做法）。
- 导入 CSS：`import 'cropperjs/dist/cropper.css'`（SSR 构建下 Vite 可正常处理）。

**3. 修改 `src/views/page/ProfilePage.vue`**
- `onAvatarSelected`：保留现有 MIME 白名单与原文件 2MB 校验，校验通过后不再直接上传，而是 `pendingAvatarFile.value = file` + `cropDialogVisible.value = true`。
- 新增 `onAvatarCropped(blob: Blob)`：若 `blob.size > 2*1024*1024` 则 `ElMessage.warning(t('profile.avatarTooLarge'))`（对齐后端硬限制）；否则 `FormData` `append('file', blob, 'avatar.png')`，复用现有 `post<ProfileData>('/api/profile/avatar', ...)` 流程（avatarUploading 状态、applyProfile、成功提示均不变）。blob.type 为 image/png，通过后端魔数校验。
- 模板：在隐藏 file input 旁加 `<AvatarCropDialog v-model="cropDialogVisible" :file="pendingAvatarFile" @confirm="onAvatarCropped" />`。

**4. 修改 `src/i18n/locales/zh-CN.ts`**（`profile` 段，紧跟 `avatarTypeInvalid` 之后，约 L210）
- `avatarCropTitle: '裁剪头像'`、`avatarCropConfirm: '确认并上传'`、`avatarCropCancel: '取消'`、`avatarCropHint: '拖动调整位置，滚轮缩放图片'`。

## 注意点
- 裁剪输出统一为 PNG：GIF 动图经裁剪会退化为静态图（原选择校验仍允许 GIF，属可接受行为）。
- 不改后端；`avatarEnabled` 门控逻辑保持不变。

## 验证
1. `learning-program-frontend` 下执行 `pnpm install`、`pnpm run type-check`（vue-tsc）。
2. `pnpm run build-only` 通过（改动涉及 SFC/CSS，顺带确认 SSR 构建 `pnpm run build:ssr` 不受影响）。
3. 启动 dev server，用浏览器测试：登录 → 个人信息页 → 更换头像 → 弹窗出现裁剪框，拖动/滚轮缩放 → 确认并上传 → 头像刷新（需后端启用 OSS 的环境；若后端不可用则只验证弹窗交互与构建结果，并如实说明）。
